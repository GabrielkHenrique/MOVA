# MOVA — Hardware Diagnostic Mode

## Overview
To assist in physical validation and threshold tuning, the ESP32 firmware includes a serial-based diagnostic mode. This mode is designed to be lightweight and strictly for developer use over USB (Serial Monitor).

## Serial Output Specification

During normal operation, the firmware prints the following upon detecting an impact:
```text
[IMPACT] Zone=center | ADC=1840 | Intensity=0.45 | JSON={"type":"footstep"...}
```

### Advanced Diagnostics (To be enabled in firmware via `#define DIAGNOSTIC_MODE 1`)
When diagnostic mode is enabled, the firmware bypasses the threshold filter and prints raw data for every loop cycle where `ADC > 100`. This allows visualizing the noise floor and the full shape of the impact wave.

**Output format:**
```text
[RAW] 1234, 1250, 1500, 2800, 3100, 1800, 400 ...
```

This raw CSV data can be copied from the Serial Monitor into the **Arduino Serial Plotter** (Tools -> Serial Plotter) to visually inspect:
1. The ambient noise floor thickness.
2. The voltage spike generated by the physical step.
3. The decay time of the piezo (to tune the 220ms refractory period).

## Current Status
* **Design:** DESIGNED
* **Implementation:** The basic `[IMPACT]` log is implemented. The continuous `[RAW]` stream is documented here as the fallback if the basic threshold logic fails during physical testing.
* **Physical Validation:** PENDING

*Note: Do not leave Diagnostic Mode enabled during actual gameplay, as printing raw data at high frequency over Serial will block the ESP32 main loop and induce severe latency.*
